# 系统架构说明

最终控制主线采用 ROS 2 节点分层。Odin1 负责传感器与定位，策略负责运动决策，硬件桥接负责 CAN 执行和最后的安全边界。

## 总体数据流

```text
Odin1
  -> odin_ros_driver
  -> IMU / odometry / cloud_slam / map->odom
  -> sim2real_hw -------------+
  -> odom_relay -> /odom      |
                              v
路线 / 导航 -> cmd_vel_nav -> cmd_mux -> /cmd_vel
                              |
                              v
                     sim2real_runtime
                     53D observation
                     ONNX / TensorRT
                              |
                              v
                     RuntimeTarget
                              |
                              v
                     sim2real_hw
                     CAN -> 电机
```

## Odin1 接口

| Odin1 输出 | 系统用途 | 下游模块 |
| --- | --- | --- |
| `/odin1/imu` | 三轴角速度、加速度和姿态估计输入 | `sim2real_hw`、策略观测、安全监控 |
| `/odin1/odometry` | 连续里程计 | `odom_relay_node`、导航 |
| `map -> odom` TF | 重定位后的全局坐标基准 | 路线跟踪、任务状态和策略切换 |
| `/odin1/cloud_slam` | 扫图、点云显示和地图处理 | Odin1 工具链、离线打点 |

`odom_relay_node` 将 `/odin1/odometry` 中继为 `/odom`，并将机体帧统一为 `base_link`。重定位模式下，Odin1 发布 `map -> odom`；纯里程计模式下不加载重定位地图，避免两个定位源同时发布冲突坐标。

## 控制模块职责

- `sim2real_bringup`：统一启动节点，并选择 Odin1 配置、定位模式和运行参数。
- `sim2real_hw`：以约 `200Hz` 读取关节、IMU 和诊断状态，发布 `RuntimeState`，消费 `RuntimeTarget`，执行 CAN 映射和超时保护。
- `sim2real_runtime`：以约 `50Hz` 根据部署契约构建 `53D` 观测，执行策略推理，输出 16 维目标。
- `sim2real_interfaces`：定义 `RuntimeState` 和 `RuntimeTarget`，隔离硬件状态与策略目标。
- `sim2real_common`：集中保存观测/动作维度、关节顺序、零位、方向、动作缩放、Mahony 滤波和安全限制。
- `sim2real_nav2` 与 `sim2real_runtime` 内的导航节点：读取路线和定位结果，发布 `cmd_vel_nav`。
- `cmd_mux_node.py`：在遥控器、Web、导航和急停之间进行模式选择、限幅和加速度限制。

## 策略观测契约

当前策略观测为 `53D`：

```text
base_ang_vel       3
projected_gravity  3
command            3
joint_pos_rel     12
joint_vel_rel     12
wheel_vel          4
last_actions      16
```

动作输出为 `16D`，前 12 维对应腿部关节，后 4 维对应轮电机。关节顺序、CAN 总线、CAN ID、方向、零位和动作缩放统一以 `src/sim2real_common/include/sim2real_common/deployment_contract.hpp` 为准。

## 安全边界

```text
estop > hardware timeout > runtime guard > safety hold > remote/web/nav
```

策略异常时，硬件桥接仍会执行目标限幅、姿态保护、电机通信超时和安全保持。Odin1 的 IMU 数据既进入策略观测，也独立参与倾角、角速度和传感器新鲜度检查。
