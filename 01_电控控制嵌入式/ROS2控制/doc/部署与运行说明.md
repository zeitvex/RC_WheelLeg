# 部署与运行说明

本文档只描述最终 ROS 2 控制主线。扫图、保存地图和重定位地图准备见 `04_定位/doc/`。

## 环境

- Ubuntu 22.04
- ROS 2 Humble
- C++17
- Python 3.10+
- `colcon`
- ONNX Runtime
- 可选 CUDA / TensorRT

实机运行还需要 Odin1、双路 SocketCAN 和与策略契约匹配的 16 个电机。电机 ID、方向、零位和动作缩放见：

```text
src/sim2real_common/include/sim2real_common/deployment_contract.hpp
```

## 构建

在 `ROS2控制/` 目录执行：

```bash
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --merge-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

只修改策略运行或启动参数时，可以只构建相关包：

```bash
colcon build --packages-select sim2real_runtime sim2real_bringup \
  --symlink-install --merge-install
source install/setup.bash
```

## 两个启动脚本

### `runros.sh`

这是 Odin1 驱动环境脚本：

- `source ./runros.sh`：加载 ROS 2 和当前工作区环境；
- `./runros.sh`：默认启动 `odin_ros_driver/odin1_ros2.launch.py`；
- `./runros.sh --shell`：进入已加载环境的交互终端；
- `./runros.sh <command>`：在已加载环境中执行命令。

它适合单独扫图、检查 Odin1 话题或进行重定位调试，不会自动启动完整的机器人策略控制栈。

### `start_sim2real.sh`

这是最终 ROS 2 控制入口，会启动策略运行、硬件桥接、命令仲裁、遥控/Web 接口、导航节点和 Odin1 驱动：

```bash
./start_sim2real.sh
```

首次联调建议先使用 dry-run：

```bash
./start_sim2real.sh \
  dry_run:=true \
  launch_driver:=false \
  launch_remote:=false \
  launch_simple_nav:=true \
  localization_mode:=odom
```

完整 Odin1 重定位控制入口：

```bash
./start_sim2real.sh \
  dry_run:=false \
  launch_driver:=true \
  launch_nav2:=false \
  localization_mode:=relocal
```

默认重定位配置为：

```text
src/odin_ros_driver/config/control_command_relocal.yaml
```

使用前必须把其中的 `relocalization_map_abs_path` 改成目标机上的真实 `.bin` 地图路径。纯里程计模式使用 `control_command_odom.yaml`，不需要 `.bin` 地图。

## SocketCAN

确认电机 ID、方向、零位、急停和支撑状态后，再配置 CAN：

```bash
sudo ip link set can0 up type can bitrate 1000000
sudo ip link set can1 up type can bitrate 1000000
./start_sim2real.sh dry_run:=false
```

## 启动后检查

```bash
ros2 node list
ros2 topic list
ros2 topic echo /odin1/imu
ros2 topic echo /odin1/odometry
ros2 topic echo /runtime/state
ros2 topic echo /runtime/target
ros2 topic echo /tf
```

确认顺序：

1. Odin1 驱动连接正常，IMU 和里程计持续更新；
2. 重定位模式下出现有效 `map -> odom`；
3. `RuntimeState` 和策略目标持续发布；
4. dry-run 正常后再接入 CAN；
5. 支架低速测试通过后再进入地面和比赛路线测试。
