# 调试与安全说明

## 命令输入

控制命令统一经过 `cmd_mux_node.py`，再进入策略运行时：

```text
遥控器 -> /cmd_vel_remote
Web    -> /cmd_vel_web
导航   -> /cmd_vel_nav
                         \
                          -> cmd_mux -> /cmd_vel -> 策略
急停   -> /safety/estop
```

`/cmd_vel` 不是直接的电机指令，而是策略的运动命令输入。Odin1 的定位结果由导航节点转换为 `vx / vy / wz`，再进入策略观测。

## 常用检查

```bash
ros2 topic echo /cmd_vel
ros2 topic echo /cmd_vel_nav
ros2 topic echo /control/mode_state
ros2 topic echo /control/mux_status
ros2 topic echo /safety/estop
ros2 topic echo /runtime/target --field target_source
```

遥控器串口和通道参数位于：

```text
src/sim2real_bringup/config/runtime.yaml
```

Web 调试默认使用目标机的 `18080` HTTP 端口和 `15000` UDP 端口。Web、遥控器和导航只能通过仲裁器改变速度命令，不能绕过硬件安全边界。

## 定位模式

- `relocal`：Odin1 加载 `.bin` 地图并输出 `map -> odom`，用于比赛路线；
- `odom`：使用 Odin1 的连续里程计，适合无地图联调或重定位不可用时的短时测试。

两种模式不要同时作为定位源运行。重新扫图或更换 `.bin` 地图后，需要重新确认点云、路线和 `map` 坐标系一致。

## 上车检查顺序

1. `dry_run:=true` 检查节点、参数、Odin1 话题和策略模型；
2. 不下发电机，检查 `RuntimeState`、`RuntimeTarget` 和观测频率；
3. 空载接入 CAN，确认电机 ID、方向、零位和反馈；
4. 机器人架空，确认站立过渡、目标超时、姿态保护和急停；
5. 支架低速测试，确认策略动作和轮腿方向；
6. 地面低速测试，逐步放开速度和任务路线；
7. 最后接入重定位路线，记录日志、视频和运行结果。

## 保护逻辑

```text
estop > hardware timeout > runtime guard > safety hold > remote/web/nav
```

以下任一条件异常时，不应继续放大速度或动作范围：

- Odin1 IMU 或里程计数据过期；
- 重定位坐标跳变或 `map -> odom` 不稳定；
- 策略目标超出动作、速度或姿态限制；
- CAN 反馈丢失、电机温度/电流/电压异常；
- 遥控器、Web 或导航命令超时。

实机调试必须保留物理急停和可人工接管的遥控器。
