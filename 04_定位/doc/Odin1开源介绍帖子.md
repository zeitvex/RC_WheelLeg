# 基于 Odin1 的机器人感知与定位开源

大家好，我们是 RC_WheelLeg 项目团队。

这次开源的主要内容是 Odin1 在轮腿机器人中的实际应用，包括传感器接入、环境感知、地图构建、重定位以及与上层规划和控制模块的连接。

对我们来说，Odin1 不只是一个单独的传感器，而是机器人感知和定位链路的基础。Odin1 为我们的团队省下了一整个视觉组的工作，使我们能够有更多的时间去准备其他的工作。

## 1. 项目背景

机器人在真实场地中运行时，除了要完成运动控制，还需要知道自己当前的位置、姿态和周围环境。

如果分别使用普通 IMU、摄像头和激光雷达，团队需要自行处理多个设备的驱动、通信、时间同步、坐标系标定以及数据融合。对于比赛项目来说，这些基础工作会占用较多的调试时间。

Odin1 是一套以激光雷达为核心、集成 IMU、RGB 摄像头和点云感知能力的三合一传感器，并通过 `odin_ros_driver` 接入 ROS 2。我们可以直接获得惯性数据、图像、点云、里程计和 TF，并将这些信息提供给上层模块使用。

在本次比赛中，Odin1 的集成大幅精简了队伍的感知开发工作量，相当于节省了一整个视觉组的人力投入，使团队能够将更多时间与精力集中在运动控制、策略调试和赛场优化等核心环节上。

## 2. Odin1 在项目里解决了什么问题

Odin1 主要解决了机器人感知和定位链路中的几个基础问题：

- 统一接入 IMU、摄像头和激光雷达；
- 减少多个传感器分别驱动和调试的工作量；
- 为机器人提供连续的 IMU 和里程计信息；
- 使用激光雷达点云完成场地扫描和地图构建；
- 在机器人重新启动或更换位置后恢复到已有地图；
- 将定位结果以 ROS 2 话题和 TF 的形式提供给规划、导航和控制模块。

因此，Odin1 的作用不是替代机器人控制算法，而是让机器人具备稳定的环境感知和位置输入，使上层控制、规划和比赛任务能够建立在可靠的传感器数据之上。

## 3. Odin1 在整机系统中的职责

Odin1 在项目中的主要职责可以概括为：

```text
Odin1
  -> odin_ros_driver
  -> IMU / 图像 / 点云 / 里程计 / TF
  -> 建图与重定位
  -> 规划 / 控制 / 比赛任务
```

具体来说：

- **IMU**：提供角速度、线加速度和连续的惯性状态输入；
- **摄像头**：提供图像数据，供系统进行视觉信息获取；
- **激光雷达**：提供点云，用于环境扫描、建图和定位；
- **里程计与 TF**：为上层模块提供机器人运动状态和坐标变换；
- **建图与重定位**：建立场地地图，并在已有地图中恢复机器人位置。

Odin1 不负责最终的运动决策，也不直接生成机器人的关节控制量。规划、决策和控制模块根据 Odin1 提供的状态与环境信息，生成机器人实际执行的运动指令。

## 4. IMU 的使用

Odin1 的 IMU 数据通过以下 ROS 2 话题发布：

```text
/odin1/imu
```

在本项目中，IMU 主要用于：

- 获取机器人机身的姿态变化；
- 为状态估计和控制模块提供惯性输入；
- 辅助里程计和定位过程；
- 判断机器人启动、运动和重定位时的状态。

我们关注的不是单独的一帧数据，而是 IMU 在整机运行中的稳定性，包括静止时输出、重力方向、角速度变化、时间戳连续性以及坐标轴方向是否正确。

在 Sim2Real 运动控制链路中，Odin1 的 IMU 经过 Mahony 姿态滤波后，提供三轴角速度和三维投影重力，直接构成强化学习策略 53 维观测中的 6 维。全局定位结果还会被导航模块转换为 `vx / vy / wz` 目标速度，间接影响策略输入。

此外，IMU 独立参与倾角保护、角速度异常检测和安全制动，作为不依赖策略网络的安全保障。

## 5. 扫图、建图与重定位

Odin1 通过 `custom_map_mode` 选择工作模式：

```yaml
register_keys:
  custom_map_mode: 0
```

对应关系为：

```text
0 -> 里程计模式
1 -> SLAM 建图模式
2 -> 重定位模式
```

### 5.1 建图

将 `custom_map_mode` 设置为 `1`，启动 Odin1 后缓慢移动设备，覆盖需要使用的区域。确认点云和轨迹正常后，在工作区保存地图：

```bash
cd <workspace>
./save_map.sh
```

生成的地图通常为 `.bin` 文件，后续可用于重定位。

### 5.2 重定位

将工作模式设置为 `2`，并指定已有地图：

```yaml
register_keys:
  custom_map_mode: 2
  relocalization_map_abs_path: "<workspace>/src/odin_ros_driver/map/xxx.bin"
  custom_init_pos: [x, y, z, qx, qy, qz, qw]
```

其中 `custom_init_pos` 是可选的初始位姿。如果能够确定机器人在地图中的大致位置，填写接近实际位置的初始位姿可以帮助系统更快完成匹配。

重定位成功后，`/tf` 中会出现：

```text
map -> odom
```

这表示机器人当前的里程计坐标已经与地图坐标建立联系，规划和导航模块可以继续使用统一的地图坐标。

## 6. 比赛中的实际应用

在比赛中，我们将 Odin1 的能力拆分为两条链路：

- **主链路：地图重定位**。基于赛前构建的赛场点云地图输出全局位姿，为 29 个路点导航提供统一的 `map` 坐标系基准；
- **兜底链路：IMU 融合 odom 导航**。当重定位短暂失效时，使用 IMU 和里程计维持短时导航。

实际比赛中，兜底链路全程未触发。赛前 1 分钟准备阶段，Odin1 重定位用时不到 15 秒完成，随后全程依靠 Odin1 稳定导航。

导航功能围绕 Odin1 导出的两类文件实现：

- `bin` 文件用于加载重定位地图；
- `pcd` 点云图配合自研打点工具规划比赛路径。

导航程序根据 Odin1 提供的全局位姿计算路点误差并生成 `vx / vy / wz`，进入不同路段后自动切换 `rough`、`crawl`、`wall` 等越障策略。因此，Odin1 的定位结果既用于确定机器人位置，也参与导航和运动策略切换。

## 8. 常用启动方式

构建并加载工作空间：

```bash
cd <workspace>
colcon build
source /opt/ros/<distro>/setup.bash
source <workspace>/install/setup.bash
```

启动 Odin1：

```bash
./runros.sh
```

也可以按工作模式启动：

```bash
./start_mapping.sh
./start_relocalization.sh /absolute/path/to/map.bin
```

启动脚本会加载 ROS 2 环境和工作空间，并启动 `odin_ros_driver` 的对应 launch 文件。

常用输出包括：

```text
/odin1/imu
/odin1/image
/odin1/cloud_raw
/odin1/cloud_slam
/odin1/odometry
/tf
```

## 9. 项目效果

本次比赛中可以量化的项目效果包括：

1. **重定位耗时**：赛前 1 分钟准备阶段，Odin1 在不到 15 秒内完成重定位；比赛过程中 IMU-odom 兜底链路未触发。
2. **自动任务完成度**：全自动控制完成 8 项障碍中的 7 项，直角绕杆因稳定性和时间权衡主动放弃，越障得分 1050 分。
3. **比赛成绩**：获得全国一等奖、全国第 7 名，进入全国前 5%。

## 10. 项目总结

本次开源主要介绍 Odin1 在轮腿机器人中的实际落地：

- 使用 Odin1 统一接入 IMU、摄像头和激光雷达；
- 通过 `odin_ros_driver` 向 ROS 2 发布传感器和定位数据；
- 使用 Odin1 完成场地扫描和地图构建；
- 加载已有地图完成机器人重定位；
- 将定位结果提供给上层规划、导航和控制模块；
- 使用 Odin1 的 IMU 支撑 Sim2Real 策略观测和安全保护；
- 为 29 个路点导航和越障策略切换提供全局位置依据。

Odin1 帮助我们减少了视觉和定位基础设施的开发工作，让团队能够把更多时间放在机器人本体、控制算法、规划和任务调试上。最终，队伍以全自动控制方案完成了本次比赛的主要障碍任务，并获得全国一等奖、全国第 7 名。
