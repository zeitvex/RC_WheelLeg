# 基于 Odin1 的轮足机器人开源项目

大家好，我们是 RC_WheelLeg 项目团队。

本次开源主要介绍 Odin1 在轮足机器人中的实际应用，包括传感器接入、IMU 数据使用、场地扫图、地图重定位，以及与上层规划和控制模块的连接。

Odin1 是一套以激光雷达为核心，集成 IMU、RGB 摄像头和点云感知能力的三合一传感器。通过 `odin_ros_driver` 接入 ROS 2 后，系统可以直接获得 IMU、图像、点云、里程计和 TF 数据。

Odin1 为我们的团队省下了一整个视觉组的工作，使我们能够有更多的时间去准备其他的工作。

## Odin1 解决的问题

在真实赛场中，机器人需要同时完成姿态估计、环境感知和全局定位。若分别使用普通 IMU、摄像头和激光雷达，团队还需要自行处理驱动、通信、时间同步、坐标标定和数据融合。

Odin1 将这些基础感知能力统一起来，为上层系统提供稳定的数据输入：

- IMU 和里程计用于状态估计与运动控制；
- 激光雷达点云用于场地扫描和地图构建；
- 已有地图用于机器人启动后的重定位；
- 图像和点云数据可供上层感知模块使用；
- ROS 话题和 TF 为规划、导航及比赛任务提供统一接口。

Odin1 负责感知与定位，不直接生成关节控制量。规划、控制和比赛任务模块根据 Odin1 输出的状态与环境信息完成机器人运动。

## IMU 与重定位

在 Sim2Real 控制链路中，Odin1 的 IMU 经过 Mahony 姿态滤波后，提供三轴角速度和三维投影重力，直接构成强化学习策略观测中的 6 维输入。同时，IMU 还参与倾角保护、角速度异常检测和安全制动。

定位链路以地图重定位为主，以 IMU 融合 odom 为短时兜底。Odin1 根据赛前构建的点云地图输出全局位姿，为导航提供统一的 `map` 坐标系；重定位成功后，系统发布：

```text
map -> odom
```

导航使用 Odin1 导出的 `.bin` 地图和 `.pcd` 点云：前者用于加载重定位地图，后者配合打点工具规划比赛路线。定位结果还用于计算路点误差和切换不同越障策略。

## 比赛中的实际效果

在比赛中，Odin1 重定位在赛前 1 分钟准备阶段用时不到 15 秒完成，IMU-odom 兜底链路全程未触发。基于 Odin1 的定位与控制系统，我们取得了以下结果：

1. 全自动完成 8 项障碍中的 7 项；
2. 越障得分 1050 分；
3. 获得全国一等奖、全国第 7 名，进入全国前 5%。

## 快速运行

Odin1 定位工作区为：

```text
04_定位/doc/
```

在 Linux/ROS 2 环境中：

```bash
cd 04_定位/doc
./build.sh
source install/setup.bash
./runros.sh
```

扫图和重定位：

```bash
./start_mapping.sh
./save_map.sh
./start_relocalization.sh /absolute/path/to/map.bin
```

常用输出包括：

```text
/odin1/imu
/odin1/image
/odin1/cloud_raw
/odin1/cloud_slam
/odin1/odometry
/tf
```

## 安全说明

- 首次运行前必须架空机器人，并确认电机 ID、方向、零位、限位和关节映射；
- 调试时必须确保遥控器、上位机或部署脚本中的急停链路可用；
- 不应在未核对机械限位、仿真模型、策略输出尺度和电机映射的情况下直接上电运行；
- 强化学习策略和 Sim2Real 部署需要先完成离线检查、仿真验证、低速空载测试和小幅动作测试；
- 本项目可能产生较大关节力矩，使用者需要自行承担硬件调试风险；
- 零位设置需在机器人稳定支撑状态下完成，并记录机身、足端、膝关节和轮组的实际姿态，避免后续模型与真机坐标不一致。
